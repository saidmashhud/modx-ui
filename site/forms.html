Forms

The fields are form-associated custom elements: inside a plain <form> they submit under their name, block submission while required and empty, follow a disabled <fieldset>, reset, and come back on back / forward navigation — through ElementInternals, no hidden inputs.

What each field submits

ElementValue in FormDatarequired means
mx-inputThe text.Not empty.
mx-selectThe value; with multiple, one entry per value.Something chosen.
mx-date-pickerYYYY-MM-DD; a range: start and end under the same name; mode="month": YYYY-MM.A value (a range: both ends).
mx-switchLike a checkbox: value (default on) while on, nothing while off.On.
mx-button—; type="submit" submits, type="reset" resets the button’s form (its form attribute works too).—

Each field also has form, validity, validationMessage, checkValidity() and reportValidity(). The browser’s message for a missing value is kitStrings.valueMissing.

const form = document.querySelector('form');
form.addEventListener('submit', (e) => {
  e.preventDefault();
  const data = new FormData(form);
  data.get('title');          // "Ship the docs"
  data.getAll('labels');      // ["docs", "design"]
  data.getAll('cycle');       // ["2026-11-02", "2026-11-15"]
});

Reset restores each field to its initial attributes (value, start / end, checked), as native inputs do.
