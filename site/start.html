Guide

Getting started

Install from npm, or vendor the repository. Load the tokens once, register the elements, and use them as HTML.

  1. Install

    From npm. lit is a peer dependency of the UI package; the store needs rxjs.

    npm install @saidmashhud/modx-ui @saidmashhud/modx-tokens lit
npm install @saidmashhud/modx-store rxjs      # optional: state and sync

    Or vendor it: the source packages point at their TypeScript (main: src/index.ts), so a copy of packages/ui, packages/tokens and packages/store in your workspace builds with any bundler (Vite, esbuild, Rollup) and no build step of its own. No decorators: any TypeScript setting works.

  2. Load the tokens

    Once, before the first element renders. They are CSS custom properties on :root; the elements read them through their shadow roots.

    import '@saidmashhud/modx-tokens/tokens.css';

    Without a bundler, link node_modules/@saidmashhud/modx-tokens/tokens.css from your HTML.

  3. Register the elements

    Everything at once, or only what a page uses (each module registers its own tags; the package marks them as side effects).

    import '@saidmashhud/modx-ui';                  // all mx-* elements
import '@saidmashhud/modx-ui/pickers.js';       // or: mx-select and mx-date-picker only
import { openPicker, setKitStrings } from '@saidmashhud/modx-ui';

  4. Use them

    Attributes for strings, numbers and booleans; properties for arrays and objects (options, items). Events are mx-* CustomEvents that bubble and cross shadow roots.

Set the page up

  • Give body the kit’s ground and text: background: var(--mx-bg); color: var(--mx-text); font-family: var(--mx-font-sans).
  • Load Inter and Space Grotesk (the families --mx-font-sans and --mx-font-display name), or override those two properties.
  • Pick a theme: dark is the default; data-theme="light" or "auto" on <html>. See Theming.
  • Phones: call trackViewport() from the tokens package once, so sheets and full-screen dialogs stay above the on-screen keyboard.

Browser support

Current Chromium, Firefox and Safari (WebKit), the engines the tests run in. The kit relies on the Popover API, <dialog>, :dir(), color-mix(), CSS logical properties and ElementInternals — Chrome 125+, Firefox 125+ and Safari 17.4+ have all of them. Where ElementInternals is missing the fields still work; they just do not take part in form submission.

Editors and tooling

The UI package ships a Custom Elements Manifest ("customElements": "./custom-elements.json" in its package.json). Editors and tools that read it (VS Code custom data generators, Storybook, linters) know every tag, attribute, event, slot and CSS part. These docs build their API tables from the same file.
